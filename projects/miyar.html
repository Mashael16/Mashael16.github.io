Miyar · معيار

Evaluating performance as work happens, using transparent business rules with AI as a second opinion.

Overview

Miyar is a performance evaluation platform built around a simple idea: employees should receive feedback based on the work they complete, not only on a manager’s memory at the end of the year. The system automatically creates a task evaluation, calculates a transparent score, and offers AI-assisted checks and feedback.

The problem

Annual reviews can be affected by recency and subjective impressions. Without recorded task-by-task evidence, managers may struggle to explain a rating, and employees have limited visibility into their performance trends.

How I solved it

When an employee submits a task, a Django signal creates an evaluation. A deterministic scoring engine assigns a 0–5 score from quality, deadlines, conduct, attendance, and task importance. Before a manager saves a rating, two Random Forest models provide an expected score and flag possible inconsistencies. An LLM produces structured natural-language insights from recorded metrics.

What I built

Explainable scoring

Weighted business rules and a task-importance multiplier produce a score employees can understand.

Machine-learning checks

A Random Forest regressor predicts an expected score; a classifier flags ratings that appear inconsistent with the evidence.

Written insights

Llama 3.1 via Groq generates structured JSON feedback on strengths and opportunities to improve.

Better task assignment

Ranks five suggested employees for new tasks using quality and on-time delivery history.

Secure APIs

JWT authentication, role-based permissions, service-layer logic, and OpenAPI/Swagger documentation.

A key engineering decision

AI supports the evaluation process, but it does not determine an employee’s score. The final score comes from explicit, deterministic rules. This separation keeps the result explainable and reduces the risk of a model error silently changing a rating.

Challenges & lessons

Making models reproducible

The locally trained models used scikit-learn 1.7, while the deployment environment had 1.5. I retrained the models in the production environment using fixed random seeds.

Deploying within infrastructure limits

With a 512 MB disk quota, I reused preinstalled scientific libraries instead of installing redundant copies.

Avoiding misleading validation

I removed features that leaked target information and used five-fold cross-validation when evaluating the Random Forest models.

What I'd improve next

The current training data is synthetic. An important next step is using real, HR-reviewed data and ensuring the training and production scoring logic share one source of truth.
