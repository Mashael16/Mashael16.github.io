Overview

Masar is a school management system for students, teachers, courses, and enrollments. It generates IDs and course codes, keeps relationships consistent, and provides an up-to-date overview of school data.

1reusable OOP core
2interfaces / one core
5main application pages

The problem

The original application worked in the terminal through a text menu and stored data as JSON. It proved the core business logic, but it was not accessible as a web experience. I wanted to add a user interface without rebuilding working classes from scratch.

How I solved it

I reused the existing Python OOP core and created a Django web layer around it. Views, templates, and forms interact with the same School class used by the console application, keeping the business logic separate from presentation.

What I built

Reusable business logic

One object-oriented core supports the console app and web interface.

Consistent relationships

Enrollment changes update both student and course records; deletion cleans up related links.

Safe user actions

POST-only deletes, CSRF protection, confirmation UI, and Post/Redirect/Get form handling.

School overview

Automatic IDs, course codes, live counts, and pages for teachers, students, courses, and enrollment.

Designed end to end

UML planning, a responsive interface, a cohesive visual system, and a custom 404 page.

A key engineering decision

Rather than replacing a working codebase with Django models, I preserved the existing School class and exposed it through a web layer. That let me focus on separation of concerns and demonstrated how one core can support multiple interfaces.

Challenges & lessons

Protecting data consistency

Adding and removing relationships needed to update both sides and clean up dependent references.

Turning scripts into web actions

I mapped existing class methods into secure Django views and templates while keeping the domain layer independent.

Preventing accidental repeats

I used the Post/Redirect/Get pattern and confirmed destructive operations before execution.

What I'd improve next

I would add attendance and grades, editing workflows, search and filtering, and authentication with distinct permissions for administrators and teachers.
